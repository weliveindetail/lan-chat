# Qwen chat: frontend

The chat page is a React app built with assistant-ui and Vite. It compiles to plain files in `lan-chat/static/`, which [server.py](../lan-chat/server.py) serves, so no Node process runs at runtime. The server's CSP did not need to change.

For the overall setup, see [2026-11-07-basic.md](2026-11-07-basic.md). For the HTTP API and install steps, see [README.md](../README.md).

## Build

Build with Node 22 or newer:

```sh
cd lan-chat/frontend
npm ci
npm run build
```

- The build replaces everything in `lan-chat/static/`.
- The server lists its static files at startup, so restart it after adding or removing files.
- An installed service reads from `/opt/lan-chat`, so the files must also be copied there. The README has the steps.
- File names are fixed (`assets/app.js`, `assets/index.css`). The server sends `no-store`, so hashed names would add nothing, and fixed names leave no stale files in `/opt`.

## Source layout

| File in `lan-chat/frontend/` | Purpose |
|---|---|
| `src/chatAdapter.js` | Custom assistant-ui adapter: sends requests, parses the stream, turns failures into message states |
| `src/App.jsx` | The chat view, Markdown rendering, progress indicator, notices, New chat |
| `src/history.js` | Saves the chat to `sessionStorage` and restores it |
| `src/styles.css` | All styling, with light and dark colours as CSS variables |
| `src/main.jsx` | Mounts the app |
| `public/favicon.svg` | Icon, which also avoids a 404 in the console |
| `vite.config.js` | Build output and CSP-safe settings |
| `.npmrc` | Turns off install scripts, pins new dependencies to exact versions, turns off audit and funding output |

## How a chat request works

1. The runtime is `useLocalRuntime(chatAdapter)`, with no `cloud` option.
2. Each send posts the full history to `/api/chat` on the page's own origin. Empty assistant turns left by failed attempts are dropped, because they carry no history.
3. The response is read with `fetch`, because `EventSource` can't send a POST or see SSE comments.
4. A `: thinking` comment sets the message's phase to `thinking`, which shows the progress indicator. Text deltas set it back to `text`.
5. Stop and New chat abort the `fetch`, which closes the connection. `server.py` then closes its connection to Ollama.

## Message states

| Situation | What the page shows | Retry button |
|---|---|---|
| Waiting for the first output | "Waiting for the model" with elapsed seconds | |
| `: thinking` received | "Thinking" with elapsed seconds | |
| `finish_reason` is `length`, with text | "Reply cut off: the output limit was reached." | Yes |
| `finish_reason` is `length`, no text | "No reply: the output limit was reached while the model was thinking." | Yes |
| `{"error": ...}` in the stream | The error text, and any partial reply stays visible | Yes |
| Stream ends without `[DONE]`, or the connection drops | "The connection ended early, so this reply is incomplete." | Yes |
| `[DONE]` with no text | "The model returned an empty reply." | Yes |
| Stop, or a reload during a reply | "Stopped." | Yes |
| 429 | The server's message that it's busy | Yes |
| 502 | "The model server is unavailable." | Yes |
| 400 or 413 | The server's message, with a suggestion to start a new chat | Yes |
| Server unreachable | "Can't reach the server." | Yes |

Retry only appears on the last message. In Firefox, a reload during a reply shows the "ended early" message instead of "Stopped.". The likely cause is that the read fails before the page unloads, but this wasn't confirmed.

## Decisions

- **Vite instead of Next.js:** only static files are needed. This also avoids Next.js telemetry, and Vite has none to turn off.
- **Plain JavaScript:** this avoids TypeScript and type packages.
- **`remark-gfm`:** added because Markdown tables don't render without it.
- **History in `sessionStorage`:** a chat survives a reload and is gone when the tab closes, so nothing stays on a shared laptop. A new tab starts empty.
- **No raw HTML:** `rehype-raw` isn't used, so HTML in replies is shown as text.
- **Images aren't loaded:** a Markdown image from the model becomes a link labelled `[Image: ...]`. The CSP would block the load anyway, and a fetch to a URL chosen by the model could leak data.
- **Links:** they open in a new tab with `noopener noreferrer`. Unsafe schemes such as `javascript:` are removed by the Markdown URL filter.
- **Enter on phones:** on touch screens, Enter adds a line and the button sends. Elsewhere, Enter sends.
- **No Copy buttons:** the page was first built for plain HTTP, where `navigator.clipboard` isn't available. Over HTTPS, the page is a secure context once the certificate is accepted, so they could be added now.
- **No login handling:** the password was removed, so the server no longer sends 401 and the page has no login states.

## CSP and privacy

The page works with this policy from `server.py`, unchanged:

```text
default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self'; font-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
```

- **Build settings:** `assetsInlineLimit: 0` keeps assets out of `data:` URLs, and the module preload polyfill is off.
- **Inline styles:** the auto-resizing composer sets styles through CSSOM, which this policy allows.
- **Components to watch:** the bundle contains `dangerouslySetInnerHTML` code from components this page doesn't render. Adding assistant-ui or Radix components could inject `<style>` elements that the policy blocks, so check the console after adding any.
- **Assistant Cloud:** it isn't used, but `@assistant-ui/react` requires the `assistant-cloud` package, so its code and `https://backend.assistant-api.com` are in the bundle. It only runs if a `cloud` option is passed, and `connect-src 'self'` would block it. A search of the bundle for URLs will find that address.

|---|---|---|

| `@assistant-ui/react-markdown` | 0.14.24 | Markdown rendering |

| `vite` (build only) | 8.3.6 | Build |
| `@vitejs/plugin-react` (build only) | 6.2.1 | JSX in the build |

No package needs its install scripts. `fsevents` declares one, but it is optional and macOS-only.

The JS bundle is about 930 KB, or 277 KB gzipped. The server doesn't compress it, which should be fine on a LAN.

## Testing

Last run on 2026-11-07, over HTTPS with no password:

| Test | Result |
|---|---|
| `python3 -m unittest test_server`, from `lan-chat/` | 30 of 30 pass |
| Browser suite in headless Chromium | 63 of 63 pass |
| Browser suite in headless Firefox | 63 of 63 pass |
| Short prompts against `qwen3.6:35b`, on loopback | Reply, code block, reload, history, Stop and New chat work; console clean |

- **Setup:** the browser suite used Playwright against the real `server.py` with a fake model server, bound to loopback. The hostname `lan-chat.test` was mapped to loopback inside the browser, with a throwaway self-signed certificate.
- **Faked responses:** 413, a stream without `[DONE]`, an error containing HTML, and the wide layout reply were faked in the browser. The other failure states came through the real server.
- **Console:** there were no CSP errors and no external requests. The only other messages were failed-request logs from deliberate errors, plus a Firefox warning that microtasks were reordered. That warning wasn't traced and had no visible effect.
- **Layout:** there was no horizontal page scroll at 390 px or 1366 px, in light or dark mode. Phone widths were emulated.

**The browser suite and fake model server aren't in this repository.** They were written in a temporary session folder, so they would need to be recreated or moved here to run again.

## Not tested

- Clicking through the real certificate warning, because the automated tests skip it
- The real LAN address
- Real phones and Safari
- Whether Ollama actually stops generating after a disconnect. The browser and `server.py` close their connections, but Ollama's own behaviour wasn't observed.

## After upgrading dependencies

1. Change the version in `package.json`, then run `npm install` and `npm run build`. Pin one exact version.
2. Check that `package-lock.json` adds no package that needs install scripts.
3. Open the page and check the console for CSP errors and the network log for external requests.
4. Test streaming, Stop, New chat, a reload and a code block. `useLocalRuntime` and the message `status` shape are what this app depends on most.
